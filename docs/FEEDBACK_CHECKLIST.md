# 공통평가 01 피드백 반영 기준

2026년 11월 10일 사용자가 전달한 교수자 개별 평가 비고로 아래 사유가 확인되었습니다. 이전의 추정과 구분하며 공통평가 02의 증빙 검토에 적용합니다.

| 이전 평가 항목 | 확인된 평가 비고 | 02에서 확인할 것 |
|---|---|---|
| ID 8 로컬 Server 브라우저 출력 | 주소창이 없어 localhost 확인 불가 | 02 ID 5, 6에서 실제 로컬 주소창과 API 응답 또는 사진을 한 화면에 포함 |
| ID 12 클라우드 서버 | 주소창이 없어 클라우드 주소 확인 불가 | 02 ID 8, 9에서 실제 PythonAnywhere HTTPS 주소창과 결과를 한 화면에 포함 |
| ID 14-3 게시글 수정과 삭제 | 수정 결과는 확인되나 삭제는 확인창까지만 있음 | 기능을 주장할 때 실행 전 상태와 실제 처리 완료 결과를 증빙. 확인창만으로 완료 처리하지 않음 |

이전 평가의 소스코드 적절성은 O, 서비스 동작 여부는 정상으로 기록되었습니다. 평가자가 2026년 11월 3일 21:54에 비로그인 GET으로 홈 HTTP 200, 게시물 3건의 API HTTP 200, 첫 이미지 HTTP 200을 확인했습니다. 이는 당시 01 서비스 확인이며 현재 02 클라우드 배포 완료의 증거로 사용하지 않습니다. 삭제 완료가 캡처에 없다는 비고만으로 삭제 구현 오류가 있었다고 단정하지 않습니다.

02에서는 추가 기능 10-1 전송 대기열과 재시도에 실패 당시 pending 상태와 복구 후 sent 상태를 함께, 10-2 중복 방지에는 재전송 전후 동일 게시글 ID와 게시글 수를 함께 제시합니다. 자동 테스트 로그와 실제 통신 결과는 확보했으나 요구 화면 캡처를 대신한다고 표시하지 않습니다.

- 서버 브라우저 증빙은 로컬 또는 클라우드 주소창부터 실제 응답 화면까지 함께 캡처합니다.
- UI를 열어 놓은 장면만으로 완료를 주장하지 않습니다. 수정 전후, 삭제 완료 후 목록, 서버 반영 결과를 확인합니다.
- 제공 Word 양식의 구조를 유지하고 각 관련증빙 칸에 그림을 직접 삽입합니다. 번호만 쓰고 뒤쪽에 별도 증빙 페이지를 만드는 방식을 사용하지 않습니다.
- 캡처는 문서 내부에 포함하고 충분한 해상도를 유지합니다. 모든 페이지를 실제로 렌더링해 판독 가능 여부를 확인합니다.
- 화면과 소스 코드, 실제 서버 동작이 일치하는지 각각 확인합니다. 자동 검사 통과만으로 평가 기준 충족을 단정하지 않습니다.
- Edge Client와 Android Client에서 같은 서버에 보낸 데이터가 웹과 모바일 화면에 일치하는지 확인합니다. 세부 시나리오는 Ch08과 평가 02 양식을 기준으로 확정합니다.
- 추가 기능은 최대 두 개이며, 기존 필수 기능과 중복 계산하지 않습니다. 서버와 클라이언트 구현의 등록 방식도 제공 양식을 따릅니다.
- 공통평가 01과 다른 GitHub 저장소를 사용합니다. 원본 01 프로젝트와 기존 제출 커밋을 변경하지 않습니다.
- Ch08 YOLO 강의자료와 공통평가 02 보고서 원본을 확보하고 항목을 확인했습니다. 실제 실행과 캡처가 끝난 항목만 완료로 표시합니다.
